# Олег & Анастасия — свадебное приглашение

Готовый адаптивный сайт-лонгрид в молочных, шалфейных и шоколадных оттенках. Дата, имена и программа взяты из предоставленного примера: **2 июля 2027 года, Ульяновск**. Перед отправкой гостям подтвердите эти данные с парой.

## Самый быстрый запуск

1. Распакуйте **весь** архив `wedding-invitation.zip`.
2. Откройте папку `wedding-invitation`.
3. Откройте `index.html` двойным щелчком в Chrome или Edge.

Основной сайт работает и без интернета: фотографии, шрифты, стили и JavaScript находятся рядом. Интернет потребуется для открытия карт и отправки через Formspree, если вы её подключите. При открытии через `file://` копирование может потребовать ручного Ctrl+C — подсказка предусмотрена.

Отдельный `wedding-preview.html` — автономная копия для быстрого просмотра. Её можно открыть одним файлом. **Редактируйте исходники в папке проекта:** preview не обновляется сам.

## Запуск в VS Code и Windows

Удобный вариант с уже установленным Node.js:

```powershell
cd путь\к\wedding-invitation
npm start
```

Откройте **http://localhost:5173**. Установка пакетов (`npm install`) не нужна. Сервер использует только встроенные модули Node.js и слушает локальный компьютер. Для остановки — `Ctrl+C`. После правок обновите страницу вручную.

Если порт занят, в PowerShell:

```powershell
$env:PORT = "5174"
npm start
```

Альтернатива: откройте папку в VS Code, установите расширение Live Server и нажмите **Open with Live Server** для `index.html`. Ещё один вариант при установленном Python: `py -m http.server 5173 --bind 127.0.0.1` из папки проекта.

## Что реализовано

- Первый экран с фотографией пары, арочным обрамлением и последовательным появлением текста.
- Личное приглашение, календарь с выделенным 2 июля, отсчёт до сбора гостей.
- Скачать событие `.ics` для импорта в календарь; время корректно переводится из UTC+4.
- Программа дня с линейными иллюстрациями; два места встречи с картами.
- Дресс-код, палитра и подборки образов; фотографии открываются крупно.
- Дополнительные мудборды и раскрывающиеся пожелания гостям.
- Анкета: участие, число гостей, имена спутников, напитки, пожелания и аллергии.
- Подготовка сообщения и копирование; системная отправка на поддерживаемых устройствах.
- Подключаемая прямая отправка через Formspree, состояния ожидания, успеха и ошибки.
- Мобильное меню, клавиатурная навигация, Escape для закрытия фото и диалогов.
- `prefers-reduced-motion`: при системной настройке уменьшения движения анимации отключаются.
- Локальные шрифты с кириллицей и оптимизированные WebP-фотографии.

## Почему HTML, CSS и JavaScript

Для одного приглашения не нужна сборка React/Vue, сервер приложения или база данных. Здесь нет npm-зависимостей. Проект легко переносить, редактировать и размещать на статическом хостинге. Node.js нужен только для необязательного локального сервера и проверок.

## Что и где менять

| Файл | Назначение |
| --- | --- |
| `config.js` | Имена, дата, часовой пояс, дедлайн ответа, места, программа, отправка формы |
| `index.html` | Основной текст, структура блоков, пожелания, статические метатеги для соцсетей |
| `styles.css` | Цвета, типографика, сетки, мобильная версия, анимации |
| `app.js` | Поведение меню, фотографий, календаря и формы |
| `core.js` | Расчёт даты, формирование сообщения и календарного файла |
| `assets/images/` | Подготовленные фотографии |
| `assets/fonts/` | Локальные шрифты и их лицензии |
| `scripts/serve.mjs` | Локальный сервер без зависимостей |
| `scripts/core.test.cjs` | Проверки дат, ICS и содержимого ответов |
| `scripts/make-preview.py` | Создание автономной HTML-копии |
| `docs/QA.md` | Выполненные проверки и что проверить вручную |

В начале `styles.css`, в блоке `:root`, находятся основные цвета:

```css
--paper: #faf8f2; /* молочный */
--sage:  #edf0e5; /* светлый шалфей */
--olive: #59634b; /* оливковый */
--ink:   #403d34; /* тёплый тёмный текст */
```

Даты изменяются в `config.js`. `date` задаёт календарный день, а `startsAt` — конкретный момент начала отсчёта. Меняйте их согласованно. `+04:00` и `Europe/Samara` соответствуют Ульяновску. Необязательный `endsAt` добавит время завершения в `.ics`; сейчас оно не задано, поскольку в примере точного времени окончания нет.

Программа задаётся массивом `schedule`. Данные о времени в `ceremony`, `reception` и тексты программы следует менять согласованно. Тексты истории и пожеланий редактируются в `index.html`.

Имена и даты на странице подставляются из `config.js`. Для карточек в мессенджерах также обновите статические `<title>`, `description`, `og:title` и `og:description` в `index.html`: роботы соцсетей не обязаны запускать JavaScript. После выбора домена можно добавить абсолютные `og:url` и `og:image`.

## Как работают ответы гостей

### Сейчас: готовое сообщение

В `config.js` поле `rsvp.endpoint` оставлено пустым. После заполнения анкеты кнопка **«Подготовить ответ»** открывает сообщение. Гость копирует его и отправляет паре в привычном мессенджере. На телефонах с поддержкой Web Share появляется **«Отправить через…»**.

**Автоматической доставки в этом режиме нет.** Сайт прямо сообщает об этом. Ответы не сохраняются на сервере или в локальном хранилище браузера. Обновление страницы очистит незавершённую анкету.

### Прямая отправка: подключение Formspree

1. Создайте форму в своём аккаунте [Formspree](https://formspree.io/) и настройте получателя.
2. Скопируйте адрес формы вида `https://formspree.io/f/xxxxxxxx`.
3. В `config.js` укажите:

```js
rsvp: {
  endpoint: 'https://formspree.io/f/xxxxxxxx',
  privacyText: 'Ответ нужен только для подготовки нашего праздника.'
}
```

4. Кнопка автоматически изменится на **«Отправить ответ»**. Форма отправляет JSON с полями `name`, `phone`, `attendance`, `guests`, `companions`, `drinks`, `wishes`.
5. Проверьте на опубликованном сайте реальную доставку одного тестового ответа. Настройки получателя, ограничения сервиса и защита от спама управляются в Formspree. Если введён неверный адрес endpoint, сайт останется в режиме подготовки сообщения.

При сетевой ошибке или тайм-ауте форма не показывает успех и не очищает данные. Можно повторить попытку или подготовить сообщение вручную. При подтверждённой сервером отправке кнопка блокируется от повторного клика; редактирование поля позволяет отправить уточнённый ответ.

Сервис пока **не подключён и реальная доставка не проверялась**, поскольку нет вашего endpoint. Секретные токены и пароли в статический сайт добавлять не нужно.

## Размещение на GitHub Pages

Для этого проекта подходит публикация из ветки: сборки нет.

1. Создайте на GitHub новый **публичный** репозиторий, например `wedding-invitation`.
2. Загрузите **содержимое** папки проекта в корень репозитория. `index.html` должен оказаться непосредственно в корне, рядом с `styles.css`, `app.js`, `config.js`, `core.js`, `assets/` и `.nojekyll`.
3. Откройте **Settings → Pages**.
4. В **Build and deployment → Source** выберите **Deploy from a branch**.
5. Выберите ветку **main** и папку **/(root)**, затем **Save**.
6. Дождитесь успешной публикации и откройте адрес, показанный GitHub. Обычно он имеет вид `https://ВАШ_ЛОГИН.github.io/wedding-invitation/`.

Это бесплатный адрес на `github.io`, а не отдельный купленный домен. На бесплатном тарифе этот сценарий использует публичный репозиторий; опубликованное приглашение также доступно по ссылке. Файл `.nojekyll` отключает ненужную обработку Jekyll. Все пути к ресурсам относительные, поэтому сайт работает и в подпапке репозитория.

Если удобнее через Git (из папки проекта):

```powershell
git init
git add .
git commit -m "Create wedding invitation"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/wedding-invitation.git
git push -u origin main
```

Команды рассчитаны на **новый пустой** репозиторий. Замените `ВАШ_ЛОГИН`; авторизуйтесь обычным способом. Для дальнейших правок: `git add .`, `git commit -m "Update invitation"`, `git push` — сайт обновится после успешной публикации.

Те же статические файлы можно перенести на любой обычный статический хостинг. На этом этапе публичная публикация не выполнялась: выбор площадки оставлен за вами, как в запросе.

## Перед отправкой гостям

1. Подтвердите имена, фамилию, дату, дедлайн и всю программу с парой.
2. Уточните точный адрес хутора «Своя Ферма». В примере его нет, поэтому кнопка пока ведёт в поиск Яндекс Карт. Вставьте проверенную ссылку в `reception.mapUrl`, а адрес — в `reception.address`.
3. Выберите способ получения ответов: сообщение в мессенджере либо Formspree.
4. Проверьте приглашение на телефоне, календарь и получение тестового ответа.

## Проверки и автономная копия

```powershell
npm run check
```

Синтаксическая проверка JavaScript и семь тестов, проверяющих даты, часовой пояс, формат ICS и корректное содержимое ответов.

После правок пересоздать автономный preview (Python 3):

```powershell
py scripts/make-preview.py
```

Результат `wedding-preview.html` появится рядом с папкой проекта. Для GitHub Pages используйте обычные исходники, чтобы браузер мог кэшировать фотографии и шрифты отдельно.
